## 2. 数据模型变更（schema.py）

新增：
```sql
CREATE TABLE IF NOT EXISTS quotation_versions(
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 quotation_id INTEGER NOT NULL,
 version_no INTEGER NOT NULL,
 action TEXT DEFAULT 'update',      -- create/update/audit
 changes TEXT DEFAULT '[]',         -- JSON: [{label, old, new, item}]
 snapshot TEXT DEFAULT '{}',        -- JSON: 保存时刻的报价单全量快照
 created_at TEXT DEFAULT CURRENT_TIMESTAMP);
```

修改：`quotations` 增加 `reviewed_at TEXT`（审核时间）；`status` 取值 `报价草稿 / 正式版本`。

删除（不再建表）：`rules`、`wechat_scans`、`wechat_files`、`communication_history`、`price_list`、`settings`。

## 3. 报价单流程改版（核心需求 1）

状态机：`报价草稿 --审核--> 正式版本`；**导出 Excel 不改变状态**；**审核后再次修改自动退回报价草稿**（受控文档流程，需重新审核）。

### 接口
| 方法/路径 | 行为 |
|---|---|
| POST `/api/quotations` | 新建：status=报价草稿，写 V1 版本（action=create），不生成 Excel、不进历史 |
| PUT `/api/quotations/{id}` | 修改：与旧数据逐字段 diff → 写 V(n+1)（action=update, changes=字段级变更）；若原状态为正式版本则退回报价草稿并清空 reviewed_at |
| POST `/api/quotations/{id}/audit` | **新增**：status→正式版本，reviewed_at=now，is_formal=1；quotation_history 按 quotation_id upsert（审核多次不产生重复历史行） |
| GET `/api/quotations/{id}/versions` | **新增**：版本列表（新→旧），changes 已解析 |
| GET `/api/quotations/{id}/excel` | 不变：随时可导出当前内容，不改状态、不写历史 |

### 字段级 diff 规则（对应需求 6「修改日志精确到字段」）
- 表头字段：quote_no / quote_date / 客户 / 项目 / Provider / 币种 / 贸易条款 / 付款条款 / 有效期天数 / 备注。客户、项目、Provider 以名称显示新旧值。
- 明细按行号对比：某行字段变化记「明细N 字段: 旧 → 新」；行增加记「新增明细N」；行减少记「删除明细N」。
- 无变化的字段不记录；完全无变更的保存也记一个版本（changes=[]，界面显示"无字段变更"）。
- snapshot 存全量 JSON（含明细），供后续查看/回滚扩展。
- 同时在 activity_log 写一条摘要（`update v3: 数量: 10 → 20; ...`，截断 500 字）。

### 报价列表界面
- 列：报价号 / Date / 到期时间 / 客户 / 项目 / Provider / 状态(pill) / 金额USD / 审核时间 / 操作 / Excel
- 操作按钮：**版本**（弹窗：V n → 时间 → 变更明细列表）、**审核**（草稿时显示，confirm 后调 audit）、编辑（进快速报价载入）、复制正式单（生成副本草稿）
- 移除「正式版本」是/否列、移除保存即生成正式版逻辑。

### 快速报价界面
- 底部按钮改为：**保存**（记录版本）、**保存并导出 Excel**（保存后直接下载，状态仍为草稿）。
- 保存成功 toast 显示「已保存为版本 N」。

## 5. 报价历史全字段筛选（需求 4）

`GET /api/quotation-history` 支持查询参数（全部可选、AND 组合）：
- `quote_no` 报价号（LIKE）
- `customer` 客户名称（c.company LIKE）
- `project` 项目名称（p.project_name LIKE）
- `product` 产品名称/描述（EXISTS quotation_items.product_name/description LIKE）
- `status` 状态（精确）
- `date_from` / `date_to` 报价日期范围

界面筛选栏：报价号、客户名称、项目名称、产品名称、状态下拉、日期从/至、重置。

## 6. 产品重复校验

`POST /api/products`：新产品的全部业务字段（除 id / 时间 / 商品编码 product_code——前端自动生成不参与判定 / active）与任一在用（active=1）产品完全一致 → 返回 400「不能重复添加：已存在参数完全一致的产品（商品编码 XXX，ID N）」。编辑（PUT）不加校验。

### 6.1 导入报价自动入库产品（验收补充）

确认导入 Excel 时（`services/quotes.py.import_blob`），每条明细按下列规则同步产品库：
- 有效行（qty / unit_price / amount 不全为 0）：按 `product_name + description` 匹配在用产品；不存在则新建（`series='Imported'`、`product_code` 自动生成 CM-P-…、`standard_price_usd`=该明细单价、备注记录来源文件），并把 `quotation_items.product_id` 关联到该产品。
- 空行（数量/单价/金额全为 0 的页脚文字，如 "Total amount"、付款条款）：不生成产品、`product_id` 为空。
- 同文件重复导入按 sha256 判重，不重复建产品；同产品出现在多份报价中自动复用。
- 历史数据由 `backfill_products_from_items()` 一次性回填（含空行解绑与无引用垃圾产品清理）。

## 7. 每周自动备份（需求 3）

- `scheduler`：每 20s 巡检；`backups` 表最近一份自动备份距今 ≥ 7 天（或首次启动无任何备份）→ `run_backup('auto','每周自动备份')`。
- 文件名已含时间戳：`backup_YYYYMMDD_HHMMSS_auto.db`（SQLite 在线备份，不影响运行）。
- 保留最近 14 份（backup_retention 可在 config 表覆盖），超出自动清理。
- 无备份管理页面；`POST /api/backup/run`、`GET /api/backups` 接口保留（测试/扩展用）。
